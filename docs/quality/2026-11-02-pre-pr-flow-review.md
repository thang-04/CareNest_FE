Later counts of present days, meals and diligent children use that roster. Earlier attendance still contributes to avgPresent, so fields may disagree. Conflicts with user's earlier confirmation that joining/leaving children count in that month. Reproduce: present 1–10 October in A, end enrollment on 10 October, view A October report. Static confirmation; new real-service regression not run in this pass.
2. **P2 — monthly evaluation drafts omit children who left/transferred before period end.** BE ChildEvaluationServiceImpl.java:624 selects roster on end date. Daily evidence from the beginning of the month does not cause a draft in the old class. Existing transfer tests create the old draft before transfer, so do not cover first listing after transfer. Reproduce: record September daily data, transfer on 20 September, first list A evaluations in October. Needs regression and explicit class-history behavior when fixing.
3. **P2 — demo reward ticket count always misses normal generated tickets.** assessmentReportsMock.js:39 requires t.schoolYear, but assessmentMockRepository.js:779 makeTicket does not store it. Runtime probe with one valid WEEKLY ticket returned sourceTickets=1 and rewardWeeklyTickets=0. Thus suggestions for Bé ngoan/Bé ngoan toàn diện may be missing. Match class plus period/year boundaries, not an absent field.
4. **P2 — duplicate demo child identity changes multiple rows together.** schoolSeed.js:191 inserts ch_037 already generated by buildM1ExtraChildren. Runtime fresh seed probe: 414 rows, 413 unique IDs, duplicate ch_037. Attendance drafts use child ID as key, so this is more than a React warning.
