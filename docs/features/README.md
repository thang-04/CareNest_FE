## Cách dùng khi làm một feature

1. Tìm hàng trong bảng (hoặc grep `.ai/CONTEXT_MAP.yaml` → `keywords`).
2. Đọc module card BE (Rules, PENDING, Known pitfalls) → flow: chỉ bước `[S]` thành hành động UI.
3. Ghi rule ID liên quan vào doc feature/PR; **không chép nội dung rule**.
4. Màn hình phức tạp (nhiều trạng thái, nhiều role, có AI) ⇒ tạo `docs/features/<feature>.md` theo template dưới, thêm vào `docs/INDEX.md` và `.ai/CONTEXT_MAP.yaml` (`available.docs` + `keywords`).

## Template `docs/features/<feature>.md`

```markdown
# Feature — <tên>

Status: thiết kế | đang code | xong · BE card: `../CareNest_BE/docs/modules/<m>.md` · Rule: <ID,...>

## Actor & permission (dẫn ROUTE_MAP; actor PENDING ghi rõ)

## Màn hình & route (route thực tế, entry point, điều hướng)

## API dùng (method + path + DTO BE; endpoint chưa có ⇒ "cần thống nhất")

## Trạng thái UI (loading / empty / error / 403 / 404 / DRAFT-APPROVED)

## Server state / UI state (key cache, invalidate sau mutation nào)

## PENDING ảnh hưởng UI (ID P-xx + cách UI xử lý tạm: theo permission / cấu hình)

## Known pitfalls (1 dòng/bẫy, link incident FE nếu có)

## Test (component/e2e chính)
```

Agent: gặp bẫy UI đặc thù feature ⇒ thêm 1 dòng **Known pitfalls** vào doc feature (và link incident).

## Đón trẻ — Trả trẻ, Gọi phụ huynh (user chốt 2026-10-23, PROPOSED — chờ BE)

- Danh sách Đón trẻ: mỗi trẻ chờ đón có 2 nút **Trả trẻ** và **Gọi phụ huynh** (bỏ "Xác minh lại").
- Điều kiện có 2 nút (user chốt 2026-10-27): đang xem ngày hôm nay, trẻ chưa được trả thành công hôm nay, trẻ được điểm danh **Có mặt**. Trường hợp khác không có nút: trẻ vắng (badge "Vắng hôm nay"), trẻ chưa điểm danh (badge "Chưa điểm danh"; cả hai chỉ ở tab Tất cả), trẻ đã đón, ngày cũ. BE giả trả `409` khi ghi trả trẻ không được điểm danh Có mặt. Tab Chờ đón trống vì còn trẻ chưa điểm danh thì nói số trẻ và có nút "Điểm danh ngay". Cô quên điểm danh mà đã qua giờ khóa thì PHT/HT mở lại ngày điểm danh trước. Đề xuất cho BE: trạng thái bảng đón `UNMARKED`; chặn ghi trả khi điểm danh hôm nay khác `PRESENT`.
- **Trả trẻ**: modal so người đón với ảnh phụ huynh đã đăng ký; bấm "Khớp ảnh – trả trẻ" thì nhập giờ trả (mặc định bây giờ), ghi chú không bắt buộc, ghi nhận ngay trong modal. Modal không có nút "Người đón không khớp" (user bỏ 2026-10-23); không khớp thì đóng modal, dùng nút "Gọi phụ huynh" của dòng.
- **Gọi phụ huynh**: modal hiện số điện thoại phụ huynh, ô **Nội dung cuộc gọi** bắt buộc (cả trả và không trả; BE giả trả `422` `note`). "Không trả" (`PHONE_DECLINED`, nhãn "Gọi phụ huynh – không trả") và "Trả trẻ" (`PHONE_CONFIRMED`) đều hỏi xác nhận rồi ghi nhận ngay trong modal. Trả trẻ: giờ trả = lúc bấm, không nhập họ tên/quan hệ người đón; người đón ghi trong nội dung cuộc gọi, bảng hiện "Theo nội dung cuộc gọi" (user chốt 2026-10-24, bỏ bước sang `/pickup/result`).
- Không liên lạc được phụ huynh cũng là "Không trả", lý do ghi trong nội dung cuộc gọi; bỏ trạng thái chờ phụ huynh gọi lại. `PHONE_UNREACHABLE` chỉ còn ở bản ghi cũ.
- Đề xuất cho BE: `note` bắt buộc với `PHONE_CONFIRMED`, `PHONE_DECLINED`; không tạo mới `PHONE_UNREACHABLE`; `pickupPersonName`, `pickupPersonRelation` chỉ bắt buộc với `PHOTO_MATCH` (2026-10-24).
